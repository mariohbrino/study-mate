# Implementation Plan: Study-Mate Application-Level Components

**Branch**: `6-design-a-base-components` | **Date**: 2026-11-14 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/005-application-ui-components/spec.md`

## Summary

Provide six reusable application-level components—Header, AssignmentCard,
AssignmentList, AssignmentForm, AssignmentSearch, and Pagination—using the existing
base primitives in `src/components/ui/`. Replace the existing global Navigation
implementation with a themed Header, organize assignment components under
`src/components/assignments/`, and leave routing, persistence, authentication, and
assignment mutations with their owning application feature. Use the existing Next.js,
React, TypeScript, Tailwind, and Vitest stack; add no runtime dependency and add only
the test-specific Playwright development dependency required for E2E coverage.

## Technical Context

**Language/Version**: TypeScript 5.x, strict mode; React 19.3; Next.js 16.4.5.

**Primary Dependencies**: Existing Next.js App Router, React, Tailwind CSS 4,
`src/components/ui/`, Vitest, and React Testing Library. Add `@playwright/test` as a
test-only development dependency because the constitution requires browser E2E
coverage and the repository has no browser automation tool. No runtime dependency is
added.

**Storage**: None owned by these components. Assignment records remain owned by the
existing application/data flow and Drizzle schema.

**Testing**: Vitest with jsdom, React Testing Library, and
`@testing-library/user-event` for component behavior; Playwright for browser E2E
coverage. Run `npm run lint`, `npm run format`, `npm run typecheck`, component tests,
and E2E tests.

**Target Platform**: Responsive web browsers, with specified narrow/wide review
widths of 320px and 1440px and light/dark theme modes.

**Project Type**: Next.js App Router web application.

**Performance Goals**: No separate service-level objective. Keep data loading in
Server Components; limit client behavior to interactive components. AssignmentList
is the smallest client container for query/page state and result slicing.

**Constraints**: Preserve strict TypeScript and `@/*` imports; use existing semantic
theme utilities and base UI components; do not add product routes, persistence,
authentication, or runtime dependencies. The E2E fixture is test-mode-only, uses the
existing root route and in-memory state, and is not exposed in normal mode.

**Scale/Scope**: Six reusable application-level components, a shared assignment type
module, a result-filtering/pagination helper, a root-layout Header replacement,
focused component tests, and browser E2E coverage. Assignment collection, data loading,
page size, and persistence remain owned by the follow-on Assignment Page Integration
feature.

**Structure Decision**: Use the existing single `src/` application. Replace the
current global Navigation component with Header and update the root layout to render
only Header; group assignment-specific components in `src/components/assignments/`
and reuse `src/components/ui/`. AssignmentList owns local query/page state and composes
the controlled Search and Pagination controls. Do not add product routes. For E2E,
the existing `/` page renders an in-memory fixture only when Playwright sets
`STUDY_MATE_E2E=1`; normal application rendering is unchanged. The follow-on
Assignment Page Integration feature owns the actual assignments page, server data
loading, and persistence/actions.
