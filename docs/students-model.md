# Student Model Design

## 1. Purpose

The student model manages student records in the Study-Mate application. It provides functions for creating, retrieving, updating, and deleting student records from the PostgreSQL database.

## 2. Student Data Structure

The student model uses the existing `students` database table.

| Field     | Type   | Description                                         |
| --------- | ------ | --------------------------------------------------- |
| id        | UUID   | Unique student identifier generated by the database |
| clerkId   | String | Unique identifier from Clerk authentication         |
| timezone  | String | Student's timezone                                  |
| createdAt | Date   | Date the student record was created                 |
| updatedAt | Date   | Date the student record was last updated            |

## 3. Model Functions

The student model will provide the following operations:

- **Store:** Add a new student record.
- **Find by ID:** Retrieve a student using their UUID.
- **Find by Clerk ID:** Retrieve a student using their Clerk identifier.
- **Update:** Update an existing student's information.
- **Remove:** Remove a student record using their UUID.

## 4. Database Integration

The model will use Drizzle ORM to communicate with PostgreSQL.

A factory function named `createStudentModel` will receive a database client as a dependency and return the student model functions. This allows the application to use the configured PostgreSQL database and tests to inject a PGlite database client.

## 5. Testing

Vitest and PGlite will be used to test the student model.

Tests will cover:

- Storing a student.
- Finding a student by ID.
- Finding a student by Clerk ID.
- Updating a student's timezone.
- Removing a student.
- Handling records that do not exist.
- Preventing duplicate Clerk identifiers.

## 6. Database Relationships

A student can have multiple assignments and study sessions. These records reference the student's UUID through their `studentId` fields.

Removing a student must respect the existing database foreign-key constraints.
