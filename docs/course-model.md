# Student Model Design

## 1. Purpose

The course model manages course records in the Study-Mate application. It provides functions for creating, retrieving, updating, and deleting course records from the PostgreSQL database.

## 2. Course Data Structure

The course model uses the existing `courses` database table.

| Field     | Type   | Description                                        |
| --------- | ------ | -------------------------------------------------- |
| id        | UUID   | Unique course identifier generated by the database |
| studentId | UUID   | UUID of the student who owns the course            |
| name      | String | Course name                                        |
| createdAt | Date   | Date the course record was created                 |
| updatedAt | Date   | Date the course record was last updated            |

## 3. Model Functions

The course model will provide the following operations:

- **Get:** Retrieve a list of all courses.
- **Store:** Add a new course record.
- **Find by ID:** Retrieve a course using its UUID.
- **Update:** Update an existing course's information.
- **Remove:** Remove a course record using its UUID.

## 4. Database Integration

The model will use Drizzle ORM to communicate with PostgreSQL.

A factory function named `createCourseModel` will receive a database client as a dependency and return the course model functions. This allows the application to use the configured PostgreSQL database and tests to inject a PGlite database client.

## 5. Testing

Vitest and PGlite will be used to test the course model.

Tests will cover:

- Retrieving an empty list of courses.
- Retrieving a list of courses.
- Storing a course.
- Finding a course by ID.
- Updating a course's name.
- Removing a course.
- Handling records that do not exist.
- Preventing duplicate course names for the same student.

## 6. Database Relationships

A student can have multiple courses. Each course references the student's UUID through its `studentId` field. The combination of `studentId` and `name` is unique, so a student cannot have two courses with the same name.

Removing a student must respect the existing database foreign-key constraints without cascading the deletion to their courses.
